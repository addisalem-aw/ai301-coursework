## Where candidates come from

Any public repository. The sandbox is behind you; the field is now
all of GitHub, and your fit profile below is what keeps that
searchable. Start from repos in languages and tools you named there,
and let the profile steer where you search, not just how results are
ranked.

**Claims count again.** The Path Review house rule does not travel.
Out here a claim comment or an assignee is a stranger who got there
first, and you have no channel to coordinate with them. Read claim
signals exactly as the rubric's checks state them; do not carry the
classroom habit of claiming over someone.

**Claim upstream the moment you commit.** The rule cuts both ways:
the instant you decide to take an issue, say so on the issue itself
(a short comment: what you plan to do and roughly when). You are now
the claim signal someone else's skill will read. Deciding privately
and claiming later is how two strangers do the same work twice.

## Fit Profile

### Languages and Technologies
I have experience with Java, Spring Boot, SQL Server, REST APIs, and microservices. I am also interested in Python, JavaScript, FastAPI, PostgreSQL, automated testing, and AI application development, including large language models (LLMs) and retrieval-augmented generation (RAG).

### Kinds of Work
I prefer hands-on software development tasks, including fixing bugs, developing backend APIs, debugging application errors, integrating databases, writing unit and integration tests, and improving error handling. I prefer issues with clear expected behavior, reproducible steps, and testable solutions.

### Kinds of Projects
I prefer Java or Python backend applications, REST API services, database-driven applications, open-source developer tools, and AI-powered applications. I am especially interested in beginner-friendly to intermediate issues that help me strengthen my backend engineering and AI engineering skills.

### What I Want to Avoid
I want to avoid major architectural redesigns, large rewrites, extensive frontend design, mobile application development, specialized hardware requirements, and tasks requiring advanced domain expertise unrelated to my experience. I also want to avoid vague issues without clear reproduction steps, duplicate issues, issues that are already resolved, and changes spanning many unrelated components.

### Preferred Issue Characteristics
Prioritize open, actionable issues with a clear problem statement, a reasonable scope, an identifiable code location, and a practical way to verify the fix with tests. Prefer issues that are unassigned, have a clear contribution path, and align with my Java, Python, API, database, testing, and AI application interests.
